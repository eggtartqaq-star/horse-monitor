# Swing V6.6.0 — 用法手冊

**V6.6 冇改任何訊號規則、冇改任何鎖死參數。** 改嘅係三樣嘢:
1. **交易清單用返驗證過嘅規則。** 引擎二要「今日高 ≥ 20日高」(手冊第三節條件3)。
   你舊嘅 `daily_strong_signals.py` 漏咗呢條,所以「OOS畢業」嗰個引擎二同你每日掃出嚟嗰個唔係同一樣嘢。
2. **舊規則嘅訊號照記錄,但唔交易。** 將來用真數據比較兩者。
3. **一套規則,所有工具共用。** 掃描器、記錄簿、Telegram bot、回測都用同一套代碼。
   每次開機都會印出版本同「指紋」。

> 2026-11-24 你嘅決定:交易路徑 = 回測驗證版;引擎一照回測做(評分≥0.55、R≥2、所有級別);
> 引擎二優先佔倉位;名義上限維持 10%(A)。

## 一、第一次安裝(大約 20 分鐘)

1. 將成個 `v6.6` 資料夾放喺電腦,例如 `桌面\v6.6`。**舊 V6.4.2 檔案唔好刪,留做後備。**
2. 打開 CMD:
   ```cmd
   pip install yfinance pandas numpy requests
   ```
   V6.6 唔再需要 `ta`(指標自己計)。但做第4步對照測試嗰陣,舊引擎仍然要 `ta`。
3. **自我測試(關卡 V-2):**
   ```cmd
   cd %USERPROFILE%\Desktop\v6.6
   python selftest.py
   ```
   要見到「全部通過」(54 項)。
4. **對照測試(關卡 V-3)** —— 證明 V6.6 同你用開嘅 `ta` 版每日出一樣嘅訊號:
   ```cmd
   copy ..\dual_engine_v6_4.py .
   python parity_check.py
   ```
   過關標準:指標差 < 0.01,有訊號日子一致率 ≥ 98%(兩條路徑分開計)。
   **過關之後**,打開 `config_v66.py`,將 `"V3_對照測試": False` 改做 `True`,
   然後將輸出 copy 畀 AI 睇。
5. **真實收費(關卡 V-1):** 喺微牛搵一張成交單據(佣金、平台費、SEC/TAF、匯兌),影相畀 AI。
   如果有任何固定收費,要重新計過系統仲有冇得賺。
6. **Telegram token:** 去 @BotFather → `/revoke` → 攞新 token。詳細步驟見第五節。

## 二、每日(收市後,香港時間朝早)

雙擊 **`掃描_v66.bat`**。佢會先自動跑自我測試,唔過關就唔會掃描。

### 睇頂部印章

```
Swing V6.6.0  指紋 69b0780a3d5b  |  ...
交易路徑: bt(回測驗證版)  影子路徑: scan(只記錄)
名義上限: A(10% 一律)  B′ 關
未過關卡: V1_真實收費已核, V2_代碼測試, V3_對照測試
```

- **指紋同上面唔一樣** = 有人改過規則或設定 → 先問清楚先好交易。
- **「美股開緊市」警告** = 今日條 bar 未收市,收市後再跑。
- **「下載失敗」列表** = 嗰幾隻今日冇訊號,唔係冇事。

### 四個區

| 區 | 意思 | 點做 |
|---|---|---|
| ① 交易清單 | 回測驗證版訊號,按排名(引擎二先,之後評分) | 由 #1 開始揀,最多 2 倉(扣返現有持倉) |
| ② 舊掃描器版先有 | 例如引擎二冇突破20日高 | **唔交易**,已自動記錄 |
| ③ 被擋 | 財報、止蝕過闊、10% 上限買唔起 | 學習用 |
| ④ 你嘅持倉 | 由記錄簿讀出,計好今日止蝕位 | 引擎二:止蝕只升不降 |

**落單:** 聽日開市落。開市價偏離收市超過 1% → 重計 R值/風險,唔達標就放棄。成交後即刻設止蝕單。

**落單之後一定要記錄**(唔好用 Excel 改 csv):
```cmd
python ledger_v66.py fill open --ticker PFE --price 27.10 --shares 4 --stop 25.30 --engine E2
python ledger_v66.py fill open --ticker NFLX --price 69.40 --shares 1 --stop 64.92 --target 83.60 --engine E1
python ledger_v66.py fill close --ticker PFE --price 28.40 --reason 移動止損
```
記錄嗰陣會即刻檢查有冇違規:超上限、冇 live 訊號、揀咗排第3或之後。

## 三、每星期(星期日,5 分鐘)

```cmd
python ledger_v66.py resolve
python ledger_v66.py review
```

`review` 分兩部分:

| 部分 | 數據來源 | 用途 |
|---|---|---|
| 【1】優勢 | 每個訊號「如果做咗」嘅結果(同回測一樣嘅出場規則) | 兩條路徑、兩個引擎分開計 |
| 【3】風險 | 你真正落嘅單 | 檢查 S1–S4 |

**檢討時間表:** 已完結嘅引擎二(交易路徑)訊號夠 30 個,**同埋**記錄滿 6 個月,先做第一次正式檢討。
之前唔好下結論。20 筆交易只係測紀律,唔係測優勢。

**停止條件** —— 任何一條出現,即刻返去 A(10%)並通知 CRO,測試期內唔爭拗:

| 條件 | 觸發 |
|---|---|
| S1 | 例外倉(B′)蝕超過戶口 2% |
| S2 | 任何倉位違規:超上限、引擎一用例外、1股 > US$192.31、冇 live 訊號就入 |
| S3 | 月熔斷觸發時有例外倉未平 |
| S4 | 扣真實收費後淨盈虧 ≤ 0 |

## 五、Telegram bot

   **唔好放入 v6.6 資料夾,唔好寫入任何 .py 檔。**

## 六、TradingView(`pine/swing_v66.pine`)

1. Pine 編輯器 → 清空 → 貼上 → 加到圖表。標題應該係「Swing V6.6.0 雙引擎」。
2. **第一次編譯可能有錯**(呢度冇得編譯 Pine),將錯誤訊息 copy 畀 AI。
3. **對照:** 打開 `pine/golden_v66.csv`,揀 5 行(要包括 E2交易、E2只記錄、E1)。
   喺圖表搵返嗰日,滑鼠指住條 bar,睇 Data Window 嘅 `G_` 數值。
   比較評分、R值、止蝕%、級別、突破。**唔好比較價錢** —— TradingView 冇做派息調整。
   評分應該一樣;R值同止蝕% 差 0.1 以內算正常。
4. 選填:「引擎二入場日」填你入場嗰日,圖表會畫移動止損。
