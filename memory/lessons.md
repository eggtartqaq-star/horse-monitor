- **L-001 (2026-07-28)** — *No analyst cross-checks another analyst's headline figure.* Bloom Energy's financial report showed a $6M profit when the filed figure was an $87M loss; the correct number sat in another report **in the same package on the same day** and four analysts crossed it. Evidence: `reports/committee/2026-07-19-be-audit.md`. Action: cross-check rule routed to 床狗.
- **L-002 (2026-07-28)** — *Bad market-data vendors must be blacklisted firm-wide, not per-report.* A single vendor print produced a fictitious "dip-buying" event in the MU structure report that never happened. Evidence: `reports/committee/2026-07-18-mu-audit.md`. Action: vendor marked price-data-unusable in every subsequent brief.
- **L-003 (2026-07-28)** — *Consecutive same-direction verdicts breed narrative lock-in.* On KLAC, three independent modelling choices all erred bearish after three prior bear verdicts. Evidence: `reports/committee/2026-07-19-klac-audit.md`. Action: anti-anchoring disclosure is now mandatory in every valuation.
- **L-004 (2026-07-28)** — *A blended score hides the difference between a bad business and a good business at a bad price.* Evidence: `reports/committee/2026-07-28-intc-audit.md`. Action: scorecard rebuilt onto two axes.
- **L-005 (2026-07-28)** — *A CEO commit message is not evidence a file exists.* The MRVL moat report failed to write and was recorded as filed; two downstream reports leaned on it. Evidence: `reports/committee/2026-07-19-mrvl-audit.md`. Action: verify on disk before recording.

- **L-006 (2026-08-03)** — *Extracted code is not code until it parses.* The CEO reconstructed the Owner's V6.4 strategy from five PDFs and audited it for three days without once running `ast.parse()`. All four files fail to compile: the PDFs clipped every line at ~80 columns, and the characters were never rendered, so the loss is unrecoverable from that source. Evidence: `strategy/v6.4/README-SOURCE-FIDELITY.md`. Same disease as L-005 — treating an unverified artifact as verified. Action: run a syntax check on any extracted or generated source before reasoning about it; cost is one second.
- **L-007 (2026-08-03)** — *A baseline that can read the answer is not a baseline.* The no-skill control in the backtest-audit evaluation had repo access, and the repo contains the completed Quant audit, the corrected V6.5 code, and the review artifacts. It cited `v6.5/portfolio_sim.py` — which exists only because of the audit being tested. Evidence: `.claude/skills/backtest-audit-workspace/iteration-1/`. Action: future skill evaluations must run the control against a clean copy holding only the subject code.
- **L-008 (2026-11-24)** — *Run what you ship; a control's failure message must never point to the uncontrolled path.* The V6.6 launcher was meant to refuse to scan when the self-test failed. A single ASCII `)` inside the batch `if` block closed it early, so it **never ran the scan at all**. Its failure text also told the Owner to fall back to the old, unvalidated scanner. The CRO and the audit both passed that block; Tom caught it by reading batch semantics. Evidence: `reports/quant/2026-11-24-v66-release-code-review.md` F-1, `memory/decisions/2026-11-24-swing-v66-release.md`. Action: the launcher was rewritten with `goto` and no parentheses, plus a static lint in `selftest.py`. Where a deliverable cannot be executed here (Windows batch, Pine), lint it statically and **say so** in the hand-off.
- **L-009 (2026-11-25)** — *A paraphrase of a risk condition drifts toward permission.* Each Cantonese restatement of a CRO condition in the V6.6 README dropped a qualifying clause, and every dropped clause made trading look easier. C-6 became "repay the debit"; the CRO's rule is a cash account or margin disabled, shown by a statement. The English release note had the same weakened line, and the first re-audit scored it complete. Evidence: `reports/committee/2026-11-25-v66-2-docs-reaudit.md` A-1, §9. Action: Owner-facing restatements quote the CRO's latest wording in full. When a setting moves, grep every printed string in the package for the old location. Quoted fingerprints and counts come from committed tool output (`results/release_stamp.txt`).
- **L-010 (2026-11-25)** — *A file-format change needs a migration and a test against the previous version's files.* V6.6.2 added one column to `fills.csv`. Against a V6.6.1 file, the first new row made every later read crash, and the scanner failed on every bull day. The selftest only built fresh files, so it could not see this. The CRO found it by upgrading a real old ledger. Evidence: `reports/risk/2026-11-25-v66-2-fix-verification.md` N-12. Action: `_append_rows` upgrades old headers with a backup and refuses unknown columns; selftest now writes a previous-version file first. Any future column change ships with a case built from the old format.
- **L-011 (2026-11-25)** — *Test under the settings the documents tell the Owner to set; apply a new ruling by mechanism, not by passage.* Two failures in one day had the same root. (1) The V6.6 self-test had only ever been run at the default `account_hkd` = 10,000, while the checklist told the Owner to set his real equity. At any other value 12 checks failed, and the launcher would have said "don't trade" every day (audit X-1). (2) When the CRO's 25 Nov C-7 ruling landed, the passage that quoted it was rewritten. The neighbouring text on the same mechanisms (`--legacy`, `s2-clear`, "don't raise `account_hkd`") was left as it was, and contradicted the ruling in the easier-trading direction (audit §9 NC-1, NC-2). Evidence: `reports/committee/2026-11-25-v66-4-docs-audit.md` X-1, §9. Action: `selftest.py` now checks the Owner's real settings, then tests on defaults. It was verified at 4,497 and 12,000, and with gates and `switch_date` set. When a ruling lands, grep every Owner-facing document for each mechanism it touches before calling it applied.
- **L-012 (2026-11-26)** — *When the live rule changes, every gate that judges it must be re-pointed to it.* C-8 was amended and N-15 added on 25 Nov, so the live entry became a limit at or below a computed maximum, with no buy if the open is at or below the stop. But the V-1/S4 fee gate (`lab.py --mode feecheck`) kept simulating the old "recompute if the open is 1% off" entry. At the CRO's US$0.35 fee estimate, the old rule shows the gate passing (+0.088% per trade). The live rule fails it (−0.066%, S4). Nobody noticed for a day, because the gate printed a confident "✅" on the wrong rule. A second instance in the same study: the cash model "refilled" a reserve that positions were already paid from. That double-counted idle cash, and it flipped the 100k conclusion when Tom corrected it. Evidence: `reports/risk/2026-11-26-v66-6-verification.md` N-29; `reports/quant/2026-11-26-v66-income-study-review.md` F-2. Action: the fee gate uses `entry_rule="limit"` and a `--tif` declared before V-1 is read. A selftest case wraps the simulator and fails if the gate runs any other rule. When a live rule changes, list every simulator, gate and report that evaluates it, and re-point each one in the same release.
