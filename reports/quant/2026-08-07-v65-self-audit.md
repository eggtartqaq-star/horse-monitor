# V6.5 — Backtest Audit of the CEO's Own Code

**Auditor: 皮褸黃 (CEO), applying `.claude/skills/backtest-audit` · 2026-08-07**

> **Conflict of interest, declared.** I wrote V6.5, I claimed it fixed V6.4's defects,
> and I am now auditing it. That is not independent. It should be re-run by Tom when
> budget allows. Everything below is nonetheless reported against the skill's seven
> checks without softening.

## VERDICT: **UNPROVEN**

V6.5 fixed the *measurement of costs and portfolio realism*. It did **not** fix the
two things that decide whether an edge exists at all.

- **What V6.5 genuinely closed:** transaction costs, capital constraints, concurrency,
  drawdown reporting, same-bar look-ahead, boundary truncation, rule fragmentation.
- **What V6.5 did not touch:** the survivor-selected universe (F-01) and the absence
  of walk-forward validation (F-10).

So the instrument now reads honestly about *cost and survivability*. It still cannot
tell you whether the signal has an edge, because the sample it draws from is still
selected with hindsight and the parameters were still chosen on data that includes
the test window.

**Being better than V6.4 is not the same as being sufficient.** V6.5 is a fixed
measuring stick applied to a still-biased sample.

## Check 1 — Universe · **HIGH, unfixed and known**

`portfolio_sim.py:45` — `TICKERS` is the same hand-written 38-name list inherited from
V6.4: NVDA, AMD, MU, INTC, PLTR, COIN, MSTR, SHOP, UBER and so on. Chosen in 2026, run
over 2019–2026.

This is disclosed in `strategy/v6.5/README.md` under "已知未修" and it is the correct
call on sequencing — Tom's argument was to establish a net-of-cost edge before paying
for point-in-time data. But **disclosure is not remediation**, and the direction is
unchanged: it overstates returns, most severely for the trend engine, which buys
strength.

**Fix:** point-in-time constituent history. Unchanged from the original audit.

## Check 2 — Look-ahead · **PASS, with one real defect**

**Fixed and verified:**
- Signal computed on bar *t*, fill executed at bar *t+1*'s **open** (`portfolio_sim.py:286`).
- Regime flag lagged one bar (`REGIME_LAG_BARS = 1`), so the MA200 gate uses yesterday's
  information.
- `selftest.py` asserts the signal function is unchanged when the frame is truncated at
  bar *i* — 18 sample points, zero mismatches. That is the skill's own prescribed test
  and it passes.
- Positions open at the end are recorded as `OPEN_AT_END` and marked to market rather
  than silently dropped — the V6.4 boundary-truncation defect is gone.

**MEDIUM-1 — the stop-width cap is validated against the wrong price.**

`portfolio_sim.py:162-164` computes the stop from the **signal bar's close** and checks
the width cap against that same close. The position is then entered at the **next bar's
open** (line 286) with the stop level carried over unchanged (line 308).

So the quantity the rule checks is `(close − stop) / close`, but the risk actually taken
is `(entry − stop) / entry`. A gap between the two prices moves the real risk away from
the checked one. For Engine 2 this matters most, because it enters on **20-day-high
breakout days — precisely the days that gap.**

*Measured on synthetic data, 877 signals:*

| Engine | Intended width (mean) | Actual at entry (mean) | Max actual | Cap | Breaches |
|---|---|---|---|---|---|
| E1 | 3.72% | 3.67% | 8.92% | 15% | 0.0% |
| E2 | 5.28% | 5.36% | 10.57% | 12% | 0.0% |

**The measurement does not settle it, and I will not present it as if it does.** The
synthetic generator draws opens within ~0.3% of the prior close — *I chose that
distribution*. Real breakout days gap far harder. The mechanism is confirmed; the
magnitude is unmeasured on real data.

**Fix (applied 2026-08-07, and re-tested):** the gate now recomputes the width against
the actual fill price and rejects the entry if it exceeds the cap, logging
`跳空後止蝕過闊`. Sizing already used `entry − stop` correctly, so only the gate was
wrong, never the position size. All 20 self-test assertions still pass.

**How often it binds — measured, and the answer is "rarely".** With `stop = close·(1−w)`
and `entry = close·(1+g)`, the realised width is `(g+w)/(1+g)`:

| signal-bar width | gap +0% | gap +2% | gap +5% |
|---|---|---|---|
| 5.0% | 5.00% | 6.86% | 9.52% |
| 10.0% | 10.00% | 11.76% | **14.29% blocked** |
| 11.5% | 11.50% | **13.24% blocked** | **15.71% blocked** |

The gate binds only when a near-cap signal meets a sizeable upward gap. Re-running the
simulation with a 2%-sd gap distribution, it fired **0 times in 117 trades** — and zero
trades exceeded their cap at entry either way. The branch is reachable and correct
(verified directly: entry 100 / stop 86 → 14.0% → BLOCK), it is simply seldom binding.

**Reported as MEDIUM, not HIGH, and deliberately not sold as a big win.** The mechanism
was real and the control was checking the wrong quantity; the measured impact is small.
Both statements are true and the second does not cancel the first.

**Note what this says about testing.** `selftest.py` passes 20 assertions including a
look-ahead check — and missed this entirely, because a test only checks what its author
already thought of. An audit found it in ten minutes. That is the argument for auditing
code you have already tested.

## Check 3 — Costs · **PASS**

`risk_config.py` applies commission, half-spread, slippage and FX on **both legs** of
every fill, across four broker scenarios. Independently reproduced the Quant
department's figures to within 0.06pp (0.74 / 1.75 / 3.38% round trip). Stop fills use
`min(stop, Open)`, so a gap through the stop fills at the open rather than pretending
the stop price was achieved.

The `--mode compare` output makes the cost sensitivity the headline rather than a
footnote. This check is fully closed.

## Check 4 — Portfolio realism · **PASS**

Real cash ledger from `US$1,282`. Integer share sizing. Six independent blocking
conditions in `plan_position()`, each naming which limit bit: concurrency cap, sector
cap, portfolio heat cap, affordability, single-position notional (10%), and cash floor.
Self-test asserts cash never goes negative and concurrency never exceeds the cap.

**The rejection log is the standout.** Every blocked signal is recorded with its reason,
which converts "the account is too small" from an opinion into a count.

**MEDIUM-2 — the drawdown circuit breaker never resets.** Once cumulative drawdown
exceeds `drawdown_budget_pct` (20%), the daily loop `continue`s past signal generation
for **every remaining day of the run**, unless equity recovers to within 20% of the
prior peak — which, with no new entries permitted, it usually cannot. In practice it is
a one-way kill switch, not a circuit breaker. That may be the intended behaviour, but it
is not what the name implies and it is not documented. **Fix:** either document it as a
terminal halt, or add an explicit re-arm rule.

## Check 5 — Overfitting · **UNFIXED**

`rules.py` carries **21 hand-tuned numeric thresholds** (scanner count), copied from
V6.4 deliberately and unchanged so that any EV difference would be attributable to the
measurement fix rather than a strategy change. That was the right call for this step and
the wrong place to stop.

The parameters were still selected on data that includes the test window. There is still
no walk-forward, no purging, no embargo, and no deflated Sharpe. **Fix:** Tom's U-3 and
U-4, unchanged.

## Check 6 — Reporting · **PASS**

`report()` prints the ugly numbers first and by name — "── 先講醜嘅 ──": max drawdown,
drawdown duration (with an explicit flag when it never recovers), worst month, worst
single trade, 5th-percentile trade, and the worst five trades individually. Return, then
Sharpe and Sortino, come afterwards. Exposure is reported so idle capital is visible.

This is the check V6.4 failed hardest and it is now the strongest part of the file.

## Check 7 — Parity · **PARTIAL**

`rules.py` is a genuine single source of truth for the Python side, and `NOTE_PINE_PARITY`
documents the four known divergences against the Pine indicator in a table.

But **Pine still cannot import it.** The table is maintained by hand, which means it will
drift again — that is what happened to V6.4. The golden-file regression test (Tom's U-6)
is specified in the note and not built. Until it exists, parity is documented rather than
enforced.

## Lower-severity

- **LOW-1 — O(n²) drawdown peak.** `portfolio_sim.py:250` recomputes
  `max(e["equity"] for e in equity_hist)` inside the daily loop. Correct but wasteful;
  a running maximum is one variable.
- **LOW-2 — holding period skips missing bars.** `pos["days"] += 1` only executes when
  the ticker has a bar on that date, so a halt or data gap silently extends the maximum
  hold beyond its nominal limit.
- **LOW-3 — the sector map is hand-made.** `SECTOR` in `portfolio_sim.py` is a rough
  manual grouping, not GICS, and it drives the per-sector cap. Labelled as such in the
  code.

## What V6.5 does right — preserve these through any rewrite

1. **Costs on both legs of every fill**, with the broker as a switch rather than an
   assumption.
2. **A real cash ledger**, so a signal that cannot be funded is recorded as rejected
   rather than silently taken.
3. **Signal at *t*, fill at *t+1* open** — the honest default, and the self-test proves
   the signal function does not read forward.
4. **Guardrails that block rather than warn**, each naming the limit that bit.
5. **The rejection log**, which turns a suspicion about account size into a number.
6. **Ugly numbers first**, by explicit design and comment.
7. **Indicators reimplemented in pandas** rather than depending on `ta`, so a library
   version bump can no longer move stop levels silently.
8. **A self-test that runs without market data.** V6.4 had a broken import nobody caught
   because nobody ran it.

## Fix order

1. **MEDIUM-1, the stop-width gate** — one line, and it is a correctness bug in a risk
   control. Do it first because it is nearly free.
2. **MEDIUM-2, document or re-arm the drawdown halt** — also nearly free, and it changes
   how every long backtest reads.
3. **Point-in-time universe (HIGH)** — still the only fix for survivorship, still gated
   on the Owner running the diagnostic first.
4. **Walk-forward + deflated Sharpe** — supersedes the current validation entirely.
5. **Pine golden-file test** — the only thing that keeps check 7 closed permanently.

**None of these change the verdict.** UNPROVEN stands until the universe and the
validation scheme are fixed, and no amount of further work on the simulator will change
that — the simulator is no longer the weak link.
