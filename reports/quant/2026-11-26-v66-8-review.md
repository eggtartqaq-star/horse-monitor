## (c) Pine: **formula PASS; F-3 cent mismatches; open check works with F-2/F-4 caveats**

**Is the selftest mirror faithful to `f_limit`? Yes, line for line.**
- Both take the minimum of three legs: cap/N, stop + risk/N, and close×1.01.
- E1 adds (target + 2×stop)/3.
- Both floor to cents with `+1e-7`.
- Both return na below the floor of the close.
- The closed form is correct: with integer N, min(⌊risk/(p−s)⌋, ⌊cap/p⌋) ≥ N holds exactly when p ≤ min(s + risk/N, cap/N).

**What the mirror does *not* test: the stop that Pine actually passes in.**
- The mirror feeds Python's share count and Python's 2-dp stop.
- Pine passes **unrounded** `stopTR`/`stopL`/`target`. Python rounds these to cents (`rules_v642.mr_plan`/`trend_plan`).
- **Measured:** 1,426 historical bt signals with A ≥ 1, in real-price periods, on the same bars (`pine_vs_py.py`):
  - share counts never differ, so `math.floor(a/b)` vs Python `//` never bites at 2-dp prices;
  - **83 limits (5.8%) differ by exactly 1¢** (70 lower in Pine, 13 higher; none na on one side only).
- **F-3 · LOW–MED.** The close alert says "唔一致就唔落,問 AI". That would make the Owner skip about 1 in 17 valid trades.
- Separately, if the Owner used one of Pine's 13 higher limits, the fill-time share check against the system stop could raise an S2.
- **Fix:**
  - in Pine, round before use: `stopTRc = math.round(stopTR, 2)`, `stopLc = math.round(stopL, 2)`, `targetc = math.round(target, 2)`, and use these in `sharesE1/E2` and `f_limit`. My mirror then drops to 12/1,426 differences, all 1¢.
  - Change the alert to "股數同限價以 Telegram 為準;差 1 仙係正常".
- The remaining 12 come from Python's `int(close*1.01*100)` having no epsilon. Over every 2-dp close from $1.00 to $399.99, that differs from `floor(…+1e-7)` in 15 of 39,900 cases.
- **F-9 · INFO:** `sizing_v66.max_limit` could add `+1e-7` in both `int()` calls. It is a core file and the lab copy must follow, so this is a later item.
- Data differences remain: TradingView prices are unadjusted, while yfinance uses `auto_adjust`, which changes ATR after an ex-date. A cents-level tolerance in the alert text is therefore needed anyway.

**Open-check alert:**
- `wasE2`/`wasE1` are computed globally on every bar. Using `x[1]` on series variables inside `if` is safe; the "call on every bar" pitfall applies to `ta.*` functions, not to the history operator.
- On a daily chart, the first realtime tick of a new session opens the new bar, and `open` is that bar's open. Its `[1]` values are the committed values of the previous session. `alert.freq_once_per_bar` fires on that first tick, because the condition is constant within the bar. **So yes, it fires at the open with that bar's open.**
- `e1Trade = basic` matches the trade path: bull, ADX < 25, score ≥ 0.55, a target with R ≥ 2, stop ≤ 15%, and A ≥ 1 share. Earnings are checked by hand, as before.
- `math.floor(x)/100` depends on v6 dividing int by int as a fraction. On the first compile, confirm that G_E1/G_E2 限價上限 show cents.

**F-2 · MEDIUM: under cancel-at-open, the broker's order status decides, not TradingView's open.**
- TradingView's realtime US open can differ by a few cents from the official opening price the order executes at, depending on the Owner's data feed.
- `ORDER_RULES` (scanner ① and the message) never says "cancel if not filled at the open". Only the message's `OPEN_CHECK` line does.
- **Fix:** add one shared `ORDER_RULES` line: "開市後即刻睇券商張單:未成交 → 取消(唔好留全日,CRO (a));已成交 → 即刻落系統止蝕單(引擎一再落止盈單)". In Pine, replace "應該已成交" with "以券商張單為準". The C-8 wording is for the CRO to confirm.

**F-4 · LOW · Pine guards:**
- The open check must run on a **daily** chart. On an intraday chart, `[1]` is the previous intraday bar. Add `timeframe.isdaily and` to both `alert()` conditions.
- Confirm on the first live day that the `freq_once_per_bar_close` close alert arrives at about 16:00 ET, not at the next open.
- Each ticker needs its own chart alert, set up before 21:30 HKT. That is an operating burden; the broker order-status check in F-2 covers it.

## (d) `send()` and the .bat files: **PASS**

**`send()`:**
- It splits by lines into parts of at most 4,000 characters, and long lines are cut. Selftest checks that nothing is lost.
- It sends each part to each allow-listed chat. With no chats configured, it sends nothing and returns False.
- Every error goes through `TB.redact` (both `description` and exceptions). The `requests` import is lazy.
- Exit codes: 0 sent; 1 scan error (the alert is still sent) or `--alert`; 3 send failed.
- **F-11 · INFO:**
  - a single line of exactly 4,000 characters would create one empty part, which Telegram rejects;
  - Telegram's limit is 4,096 UTF-16 units, and non-BMP emoji count twice. Neither matters at today's message sizes (< 1,500 characters).

**`notify_v66.bat`** (CRLF, no BOM, no ASCII parentheses, `goto` rather than `(…)` blocks; selftest checks all of these):
- selftest fails → it sends `--alert selftest`, exit 1;
- notify exits non-zero → exit 1;
- no `pause`;
- `notify_last.log` and `selftest_last.log` are gitignored.

**`schtasks /TR "\"%~dp0notify_v66.bat\""`:**
- This is the documented way to embed quotes, so paths with spaces work.
- To cmd, the path itself sits outside quotes, so a folder name containing `&` would break it. That is unlikely; note it in the checklist.
- The schedule is WEEKLY TUE–SAT at 06:30 local (HKT), which is 1.5–2.5 h after the US close all year.
- Without `/RU`, the task runs only while the Owner is logged on, as `schtasks` defaults to. That is acceptable.
- **F-10 · INFO:** after a US holiday, the next morning's message repeats the previous bar's list. The header date shows this. Optionally add "(冇新收市,同上次一樣)" when `bar_date` equals the last `runs.csv` bar.
